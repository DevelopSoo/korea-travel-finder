# Git 작업 절차

시작하기 전에 `docs/git/commit-convention.md`를 읽는다. 규칙의 원문은 이 문서이고, 아래는 진행 순서다.

## 커밋

1. `git status`, `git diff`, `git diff --staged`로 바뀐 내용을 확인한다.
2. 현재 브랜치가 `main`이면 규칙에 맞는 이름으로 새 브랜치를 만들자고 먼저 제안한다.
3. 목적이 다른 변경이 섞여 있으면 커밋을 나누자고 제안한다.
4. 비밀 정보 파일(`.env*`, 키 파일)이 있으면 스테이징에서 빼고 사용자에게 알린다.
5. 파일 이름을 직접 지정해 스테이징한다(`git add -A` 금지).
6. `타입: 한국어 요약` 형식으로 메시지를 쓰고, 끝에 시스템이 알려준 Claude 공동 작성자 표시를 붙인다. 여러 줄 메시지는 HEREDOC으로 넘긴다.
7. 커밋한 뒤 `git log --oneline -1`로 결과를 보여준다.

## push · PR

사용자가 요청했을 때만 진행한다.

1. `npm run lint`와 `npm run build`를 실행한다. 실패하면 멈추고 결과를 보고한다.
2. `git push -u origin <브랜치>`로 push한다. `main`에 push하거나 `--force`를 쓰지 않는다.
3. `gh pr create`로 PR을 만든다. 제목은 커밋 형식을, 본문은 규칙 문서의 템플릿(변경 사항 / 이유 / 확인 방법)을 따르고, 끝에 시스템이 알려준 PR 표시를 붙인다.
4. 만들어진 PR URL을 사용자에게 알려준다.

## 규칙
- hook이 실패하면 `--no-verify`로 건너뛰지 않는다. 원인을 고친 뒤 **새 커밋**을 만든다.
- 규칙 문서에 없는 상황(새 타입이 필요한 경우 등)은 임의로 정하지 말고 사용자에게 한 줄로 확인한다.
