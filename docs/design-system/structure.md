## 1. 웹사이트 구조

### 1-1. 페이지 목록

| 번호 | 페이지        | 주소                                       | 하는 일 딱 하나                              |
| ---- | ------------- | ------------------------------------------ | -------------------------------------------- |
| 1    | 첫 화면       | `/en`                                      | `Find my Korea` 버튼을 누르게 한다           |
| 2    | 질문 화면     | `/en/find`                                 | 버튼 3번 누르게 한다 (한 화면에 질문 하나)   |
| 3    | 결과 화면     | `/en/results?i=nature,local&v=many&s=slow` | 카드를 보여 주고 이메일을 받는다             |
| 4    | 경험 상세     | `/en/experiences/{slug}`                   | 한 곳을 자세히 보여 주고, 구글 검색에 걸린다 |
| 5    | 개인정보 안내 | `/en/privacy`                              | 이메일 수집 근거. 한 페이지, 글만            |
| 6    | 없는 페이지   | `/en/404`                                  | "이 경험은 아직 없어요" + 첫 화면 가기       |

결과 화면 주소에 답을 그대로 넣는 이유: 새로고침해도 결과가 유지되고, 나중에 "결과 공유 링크" 기능을 붙일 때 그대로 쓸 수 있다.

### 1-2. 페이지 흐름

```text
쇼츠 프로필 링크 (?src=tiktok)
        ↓
   [1] 첫 화면 ──────────────────────────┐
        ↓ Find my Korea                  │
   [2] 질문 1/3 → 2/3 → 3/3              │ Start over
        ↓ 마지막 답                       │
   [3] 결과 화면 ───── 이메일 보내기       │
        ↓ 카드 클릭            ↑          │
   [4] 경험 상세 ── 관련 카드 → [4] 다른 상세
        ↓ Find your Korea                │
   [2] 질문 화면 ←───────────────────────┘

구글 검색 → [4] 경험 상세 (여기서 처음 들어오는 사람도 있다)
```

상세 페이지는 **입구가 두 개**다 (결과 화면에서 오는 사람 / 구글에서 바로 오는 사람).
그래서 상세 페이지 맨 아래에 `Find your Korea` 버튼이 반드시 있어야 한다.

### 1-3. 페이지별 부품 조립

