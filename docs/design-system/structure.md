## 1. 웹사이트 구조

### 1-1. 페이지 목록

| 번호 | 페이지        | 주소                          | 하는 일 딱 하나                                  |
| ---- | ------------- | ----------------------------- | ------------------------------------------------ |
| 1    | 첫 화면       | `/en`                         | 취향 칩이나 장소 중 하나를 누르게 한다           |
| 2    | 장소 목록     | `/en/places`                  | 어디로 갈지 고르게 한다                          |
| 3    | 장소 안내     | `/en/places/{slug}`           | 그 지역이 어떤 곳인지 보여 주고 경험으로 넘긴다  |
| 4    | 경험 목록     | `/en/experiences`             | 취향·지역·시간으로 걸러 카드를 보여 준다         |
| 5    | 경험 상세     | `/en/experiences/{slug}`      | 한 경험을 자세히 보여 주고, 구글 검색에 걸린다   |
| 6    | 저장          | `/en/saved`                   | 담아 둔 경험을 지역별로 묶어 보여 준다           |
| 7    | 개인정보 안내 | `/en/privacy`                 | 저장이 어디에 남는지(기기/계정)와 문의처 안내. 글만 |
| 8    | 없는 페이지   | `/en/404`                     | 한 줄 + 경험 목록으로 가기                       |
| 9    | 로그인        | `/en/login` (`?mode=signup`)  | 원하는 사람만 로그인·가입하게 한다. 끝나면 보던 페이지로 |

개발용 `/en/dev/ui` (부품 모음)는 `NODE_ENV=production` 에서 404 가 된다.

경험 목록은 주소에 `?i=food` 를 받는다 — 첫 화면 취향 칩이 여기로 보낸다.
그 밖의 거르기(지역·시간)는 주소를 바꾸지 않는다. 화면 안에서만 좁힌다.

### 1-2. 저장은 이 기기 또는 계정에 남는다

계정은 **선택**이다. 로그인하지 않아도 모든 화면을 쓰고 저장할 수 있다.

- 로그인하지 않았으면 저장 목록은 브라우저 `localStorage` 한 곳에만 있다 (키: `ek.saved.v1`). 브라우저 데이터를 지우면 목록도 사라진다.
- 로그인했으면 저장 목록은 계정(Supabase `saved_experiences`)에 있다. 로그인하는 순간 이 기기 목록을 계정에 합치고 기기 목록은 비운다. 로그아웃하면 계정 목록은 이 기기에 남지 않는다.
- 어느 쪽이든 로그인 여부와 목록은 **브라우저에서** 읽는다 (`useAuth()`, `useSaved()`). 서버는 쿠키를 읽지 않으므로 페이지는 미리 만들어지고, 저장 화면과 머리의 `Saved (n)` 숫자는 첫 그림이 비어 있다가 브라우저에서 채워진다.
- 저장 화면의 안내 한 줄(`SavedNote`)은 로그인 여부에 따라 "이 기기에 저장 + 로그인 링크" / "계정에 저장"으로 바뀐다. 확인하는 동안에는 비워 둔다.
- 이 동작과 계정 삭제·문의 방법을 개인정보 안내에 적는다. 동작이 바뀌면 `en.json` → `privacy` 도 함께 고친다.

### 1-3. 페이지 흐름

```text
   [1] 첫 화면
    │   ├─ 취향 칩 ──────────→ [4] 경험 목록 (?i=…)
    │   ├─ 장소 카드 ────────→ [3] 장소 안내
    │   └─ Explore Korea ────→ [2] 장소 목록
    │
   [2] 장소 목록 ────────────→ [3] 장소 안내
    │
   [3] 장소 안내 ────────────→ [5] 경험 상세
    │                              │
   [4] 경험 목록 ────────────→ [5] 경험 상세
                                   ├─ 근처 경험 → [5] 다른 상세
                                   └─ 지역 안내 → [3]

   어느 화면에서든 사진 위 책갈피 ─→ [6] 저장

구글 검색 → [5] 경험 상세 (여기서 처음 들어오는 사람도 있다)
```

상세 페이지는 **입구가 두 개**다 (사이트 안에서 오는 사람 / 구글에서 바로 오는 사람).
그래서 상세 오른쪽 상자에 `View {지역} guide` 가 반드시 있어야 한다.

### 1-4. 모든 페이지의 뼈대

```text
┌──────────────────────────────────────────┐
│ 머리 (Header)                            │ ← 로고 + Places·Experiences + Saved(숫자) + Log in/out
├──────────────────────────────────────────┤
│ 길 표시 (Breadcrumb)                     │ ← 첫 화면 빼고 전부. 장소 안내만 띠 배경
├──────────────────────────────────────────┤
│                                          │
│ 몸통 (페이지마다 다름)                    │
│                                          │
├──────────────────────────────────────────┤
│ 밴드 (CtaBand)                           │ ← 페이지당 하나. 다음 걸음 하나만 권한다
├──────────────────────────────────────────┤
│ 발 (Footer)                              │ ← 로고 + 링크 3개 + 한 줄. 글자만
└──────────────────────────────────────────┘
```

- 머리는 지금 보고 있는 칸에만 밑줄을 긋는다. 색으로 표시하지 않는다.
- 머리의 `Saved (n)` 숫자는 브라우저에서 채워진다 — 서버가 그린 첫 그림에는 숫자가 없다.
- 머리의 `Log in` / `Log out` 도 브라우저에서 정해진다. 확인 전에는 자리만 비워 둔다.
- 몸통 폭은 `max-w-content`(1200px) + `gutter`. **첫 화면 사진과 시즌 밴드만 화면 끝까지 닿는다.**

### 1-5. 페이지별 부품 조립

**[1] 첫 화면**

```text
사진(화면 끝까지, 높이 420/440) — 사진 위에 h1 + 한 줄 + 버튼(종이색)
취향 칩 4개 (가운데)
장소 카드 그리드 (PC 4열)
시즌 밴드 (사진 반 / 글 반, 화면 끝까지)
```

**[3] 장소 안내**

```text
길 표시(띠 배경)
사진(화면 끝까지, 높이 340/400) — 사진 위에 눈썹 + 장소 이름 + 한 줄
소개 두 단 (왼쪽 제목·버튼 / 오른쪽 설명 글)
Plan your visit 상자 — 정보 칸 3개
그 지역 경험 카드 그리드 (PC 3열)
하루 흐름 상자 (사진 / 번호 3단계)
밴드
```

**[4] 경험 목록**

```text
길 표시
눈썹 + h1 + 한 줄 (가운데)
알약 필터 (취향, All 포함)
구분선 + 드롭다운 2개(지역·시간) + 개수
경험 카드 그리드 (PC 3열)
밴드
```

**[5] 경험 상세**

```text
길 표시 (홈 / 경험 / 지역 / 이 경험)
눈썹(그린) + h1 + 한 줄 + 저장 버튼
사진(높이 260/400) + 바로 밑에 정보 칸 4개 상자
본문 두 단 (왼쪽 글·사진 2장 / 오른쪽 요약 상자)
근처 경험 (넓은 카드, PC 3열)
안내 한 줄 (Planning note)
밴드 (저장 버튼 + 저장 목록 링크)
```

**[6] 저장**

```text
길 표시
h1 + 한 줄 + 저장 위치 안내 한 줄 (기기 / 계정)
구분선 + "Saved experiences" + 개수 + 지역 알약(두 지역 이상일 때만)
지역별 묶음 — 제목 + 개수 + 지역 안내 링크 + 넓은 카드 그리드
밴드
```

### 1-6. 반응형

판형은 PC 기준으로 잡혀 있다. 폰에서는 아래 규칙으로 접는다.

| 항목            | 폰 (~767px)          | PC (768px~)            |
| --------------- | -------------------- | ---------------------- |
| 좌우 여백       | 20px                 | 44px                   |
| 카드 그리드     | 1열                  | 2열(sm) → 3~4열(lg)    |
| 두 단 레이아웃  | 위아래로 쌓인다      | 좌우 두 단             |
| 첫 화면 `h1`    | `text-4xl` (36px)    | `text-hero` (60px)     |
| 사진 최소 높이  | 220~420px            | 320~440px              |
| 머리            | 로고 / 칸 두 줄로 접힘 | 한 줄                |
| 정보 칸 세로선  | 없음 (세로로 쌓임)   | 칸 사이 1px 세로선     |

가로 스크롤이 생기면 안 된다. 최소 폭은 320px.
