# Korea Experience Finder — PRD v1 (MVP)

> 문서 버전: v1 (2026-08-29)
> 상태: 개발 전 초안
> 관련 문서: 「대한민국 관광산업의 전체 가이드 방향 v1」, 「예상 BM 가이드 v1」

---

## 1. 한 줄 요약과 이번 버전의 목표

### 한 줄 요약

> 외국인이 버튼 3개만 누르면, 자기 취향에 맞는 "서울 밖까지 포함한 진짜 한국 경험"을 카드로 보여주고, 그 결과를 이메일로 받게 하는 작은 웹사이트.

### 이번 버전이 하려는 것 (딱 3가지)

1. 쇼츠를 보고 온 사람이 **끝까지 질문에 답하는지** 확인한다.
2. 어떤 취향 버튼이 많이 눌리는지 **데이터를 모은다.**
3. **이메일 명단**을 만든다.

### 목표 숫자 (출시 후 3개월 기준, 조정 가능)

| 항목          | 목표                   | 왜 이 숫자인가                                                           |
| ------------- | ---------------------- | ------------------------------------------------------------------------ |
| 방문자        | 3,000명                | 쇼츠 프로필 링크에서 오는 양을 보는 첫 기준                              |
| 질문 완료율   | 60% 이상               | 첫 화면에서 시작한 사람 중 결과까지 간 비율. 낮으면 질문이 지루하다는 뜻 |
| 이메일 등록률 | 결과 도달자의 15% 이상 | 결과가 쓸모 있으면 이메일을 남긴다                                       |
| 이메일 수     | 300명                  | BM 문서 1단계 목표(500명)의 절반                                         |
| 카드 클릭률   | 결과 도달자의 40% 이상 | 카드를 눌러 상세를 본다 = 관심이 있다                                    |

이 숫자는 "성공/실패"를 가르는 선이 아니라, **다음에 무엇을 고칠지 정하는 기준**이다.

## 2. 고객과 그들이 겪는 문제

### 중심 고객: 한국 재방문객

- 한국에 1번 이상 와 봤고, 다시 오려는 외국인
- 서울의 유명 관광지는 이미 봤다
- "이번엔 어디 가지? 서울 말고 뭐가 있지?"라는 질문을 실제로 한다
- 영어를 쓴다 (첫 버전은 영어권 우선)

### 입구 고객: K-culture 팬

- K-POP, K-드라마로 한국에 관심이 생긴 사람
- 검색량이 많아 유입이 쉽다
- 이들을 "K-culture, but deeper" 버튼으로 받아서 서울 밖 경험으로 연결한다

### 고객이 겪는 문제

| 문제                                           | 지금 어떻게 하고 있나      | 왜 불편한가                          |
| ---------------------------------------------- | -------------------------- | ------------------------------------ |
| 서울 밖에 뭐가 있는지 모른다                   | 구글, 유튜브, 레딧 검색    | 정보가 흩어져 있고 영어 자료가 적다  |
| 관광지 목록은 많은데 "나한테 맞는 것"을 모른다 | 블로그 "Top 10" 글         | 취향과 상관없이 똑같은 목록만 나온다 |
| 지방은 영어가 안 통할까 봐 걱정한다            | 포기하거나 서울에만 머문다 | 실제로는 갈 수 있는 곳이 많다        |
| 왜 거기를 가야 하는지 이유를 모른다            | 사진만 보고 판단           | 갔다가 실망하거나 애초에 안 간다     |

### 우리가 주는 답

- 취향 3개만 고르면 **맞는 경험만** 골라 준다
- 카드마다 **"Why here, not Seoul"** 한 줄로 이유를 준다
- 카드마다 **영어 편한 정도**를 점수로 보여 준다

## 3. 이번에 만드는 것 / 안 만드는 것

### 만드는 것 (MVP 범위)

- 화면 4장: 첫 화면, 질문 화면, 결과 화면, 경험 상세 페이지
- 단순 규칙 추천 (AI 없음)
- 이메일 수집 (결과 화면)
- 사용자가 누른 버튼과 카드를 저장
- 경험 데이터 40개 (강릉 25개 + 서울 15개)
- 영어 화면
- 다국어를 나중에 붙일 수 있는 구조 (주소 `/en/`, 언어별 문장 파일)
- 폰 화면에서 보기 편한 디자인 (쇼츠에서 오는 사람은 거의 폰이다)
- 검색 엔진이 상세 페이지를 읽을 수 있게 하기

### 안 만드는 것 (다음 버전 이후)

| 안 만드는 것                    | 이유                                                               |
| ------------------------------- | ------------------------------------------------------------------ |
| 회원가입 / 로그인               | 이메일 하나면 충분. 가입은 이탈만 늘린다                           |
| AI 챗봇, AI 추천                | 원칙 2 — 데이터가 없는데 AI부터 만들지 않는다                      |
| 지도                            | 원칙 — 지도는 만들지 않는다. 상세 페이지에서 구글 지도 링크만 연다 |
| 예약, 결제                      | 원칙 7 — 최대한 늦게                                               |
| 일정(며칠 코스) 만들기          | Phase 4. 지금은 "경험 발견"까지만                                  |
| 결과 저장 / 나중에 다시 보기    | 이메일로 결과를 보내는 것으로 대신                                 |
| 리뷰, 댓글                      | 관리 부담. 쇼츠 댓글로 대신                                        |
| 관리자 화면                     | Supabase 편집기를 그대로 쓴다                                      |
| 스페인어 등 다른 언어           | 구조만 준비, 실제 번역은 나중                                      |
| 다크 모드, 애니메이션 등 꾸미기 | 반응이 확인된 뒤                                                   |

## 4. 화면별 상세

전체 흐름:

```text
쇼츠 프로필 링크
  ↓
[1] 첫 화면
  ↓ Find my Korea 버튼
[2] 질문 화면 (3단계)
  ↓ 마지막 답 선택
[3] 결과 화면 (카드 6~8개 + 이메일 칸)
  ↓ 카드 클릭
[4] 경험 상세 페이지
```

### [1] 첫 화면 (`/en`)

**보이는 것**

- 큰 글씨: `Seoul is 1% of Korea.`
- 작은 글씨: `Tell us what you love. We'll show you the Korea you haven't seen.`
- 버튼: `Find my Korea`
- 버튼 아래 작은 글씨: `Takes 20 seconds. No sign-up.`
- 배경: 서울이 아닌 한국 사진 1장 (예: 강릉 바다, 산속 절)
- 맨 아래: 인스타/틱톡 링크, 언어 표시(지금은 `EN`만)

**누를 수 있는 것**

- `Find my Korea` → 질문 화면으로
- SNS 링크

**눌렀을 때 일어나는 일**

- "시작함" 기록을 저장 (완료율 계산용)
- 질문 화면 1단계로 이동

**설계 이유**

- 첫 화면은 딱 하나만 하게 한다. 설명이 길면 안 누른다.
- "No sign-up"을 미리 말해 주면 시작률이 올라간다.

---

### [2] 질문 화면 (`/en/find`)

한 화면에 질문 하나씩. 위에 진행 표시(1/3, 2/3, 3/3). 뒤로 가기 가능.

**질문 1 — `What do you want to feel in Korea?`** (여러 개 선택 가능, 최대 3개)

| 버튼                          | 내부 태그  |
| ----------------------------- | ---------- |
| Nature & quiet                | `nature`   |
| Local everyday life           | `local`    |
| Food you can't find elsewhere | `food`     |
| History & tradition           | `history`  |
| K-culture, but deeper         | `kculture` |
| Sea & islands                 | `sea`      |

**질문 2 — `Been to Korea before?`** (하나 선택)

| 버튼       | 내부 값 |
| ---------- | ------- |
| First time | `first` |
| Once       | `once`  |
| Many times | `many`  |

**질문 3 — `How do you travel?`** (하나 선택)

| 버튼               | 내부 태그     |
| ------------------ | ------------- |
| Slow & relaxed     | `slow`        |
| Active & outdoors  | `active`      |
| Like a local       | `local_style` |
| Comfortable & easy | `easy`        |

**눌렀을 때 일어나는 일**

- 버튼을 누르면 바로 다음 질문으로 넘어간다 (질문 1은 "Next" 버튼 필요, 나머지는 자동)
- 3번째 답을 누르는 순간 → 답 3개를 저장 → 결과 화면으로 이동
- 중간에 나가면 어디까지 답했는지도 저장 (어느 질문에서 나가는지 보려고)

**설계 이유**

- 질문 2는 추천에도 쓰이지만, "재방문객이 실제로 오는가"를 확인하는 핵심 데이터다.
- 버튼만 누르게 하고 글자 입력은 없앤다. 폰에서 타자는 이탈 원인이다.

---

### [3] 결과 화면 (`/en/results?...`)

**보이는 것**

- 제목: `Your Korea` + 고른 취향 요약 (예: `Nature · Local · Slow`)
- 카드 6~8개. 카드 하나에:
  - 사진 1장
  - 이름 (예: `Jumunjin Fish Market at Dawn`)
  - 지역 뱃지 (`Gangneung`)
  - 한 줄 설명
  - `Why here, not Seoul:` 한 줄
  - 작은 정보 3개: 걸리는 시간 / 가격대 / 영어 편한 정도(★1~5)
- 카드 목록 아래 이메일 박스:
  - `Want this list in your inbox? We'll add a few extras.`
  - 이메일 입력 칸 + `Send my list` 버튼
  - 작은 글씨: `No spam. Unsubscribe anytime.`
- 맨 아래: `Start over` 링크

**누를 수 있는 것**

- 카드 → 상세 페이지
- 이메일 보내기
- Start over → 첫 화면

**눌렀을 때 일어나는 일**

- 카드 클릭: 어떤 카드를 눌렀는지 저장 → 상세 페이지로
- 이메일 보내기: 이메일 + 이번 결과 + 고른 답을 저장 → "Sent! Check your inbox." 표시 → 결과 목록 이메일 발송
- 이메일 형식이 틀리면 빨간 글씨로 `Please check your email.`

**설계 이유**

- 이메일을 "결과를 받는 이유"로 묶으면 자연스럽다. 결과를 가리고 이메일을 요구하면 신뢰가 떨어진다.
- 카드에 "Why here, not Seoul"이 있어야 우리 브랜드가 드러난다.

---

### [4] 경험 상세 페이지 (`/en/experiences/{slug}`)

주소 예: `/en/experiences/jumunjin-fish-market-dawn`

**보이는 것**

- 사진 1~3장
- 이름, 지역
- 소개 글 (150~300단어, 영어)
- `Why here, not Seoul` 문단
- 정보 표: 걸리는 시간 / 가격대 / 가장 좋은 시간(계절·시간대) / 영어 편한 정도 / 현지감 / 예약 필요 여부
- `How to get there` 짧은 설명 + 구글 지도 링크 버튼
- `Good for:` 태그 (nature, slow …)
- `Watch:` 관련 쇼츠 링크 (있으면)
- 아래: `You might also like` 카드 3개 (같은 지역 또는 같은 태그)
- 맨 아래: `Find your Korea` 버튼 (질문 화면으로)

**누를 수 있는 것**

- 구글 지도 링크 (새 창)
- 쇼츠 링크 (새 창)
- 관련 카드 → 다른 상세 페이지
- `Find your Korea` 버튼

**눌렀을 때 일어나는 일**

- 페이지 열림 기록 저장
- 지도/쇼츠 링크 클릭 기록 저장 (나중에 제휴 링크 자리 확인용)

**설계 이유**

- 이 페이지가 구글 검색에 걸리는 콘텐츠다. 주소·제목·소개 글을 검색 친화적으로 쓴다.
- 나중에 제휴 링크(투어, 기차표)를 붙일 자리는 `How to get there` 아래다.
- 이 페이지는 배포 시점에 미리 만들어 두어(굳혀서) 빠르게 열리게 한다.

## 5. 추천 규칙

AI 없이 **점수 더하기** 방식이다.

### 규칙

1. 경험마다 태그가 붙어 있다 (예: `nature, slow, sea`).
2. 사용자 답에서 태그를 모은다.
   - 질문 1 답 → 관심 태그 (최대 3개)
   - 질문 3 답 → 스타일 태그 (1개)
3. 경험마다 점수를 계산한다:
   - 관심 태그가 하나 맞을 때마다 **+3**
   - 스타일 태그가 맞으면 **+2**
   - 질문 2가 `once` 또는 `many`이면 **서울 밖 경험에 +2** (재방문객은 서울 밖으로)
   - 질문 2가 `first`이면 **서울 경험에 +1**, 영어 편한 정도 4 이상이면 **+1**
   - `easy` 스타일이면 영어 편한 정도 4 이상에 **+1**
4. 점수 높은 순으로 정렬해 위 8개를 보여 준다.
5. 같은 지역이 8개 중 6개 이상이면 다른 지역 것 하나를 끼워 넣는다 (다양성).
6. 점수가 0인 경험은 보여 주지 않는다. 8개가 안 되면 있는 만큼만.

### 예시

사용자가 `Nature & quiet` + `Local everyday life`, `Many times`, `Slow & relaxed`를 골랐다.

| 경험                 | 태그             | 지역 | 점수 계산                     | 합계     |
| -------------------- | ---------------- | ---- | ----------------------------- | -------- |
| 주문진 새벽 어시장   | local, food, sea | 강릉 | local +3, 서울밖 +2           | 5        |
| 대관령 양떼목장 산책 | nature, slow     | 강릉 | nature +3, slow +2, 서울밖 +2 | 7        |
| 망원시장             | local, food      | 서울 | local +3                      | 3        |
| 안목해변 새벽 커피   | slow, sea, local | 강릉 | local +3, slow +2, 서울밖 +2  | 7        |
| 경복궁 야간 개장     | history          | 서울 | 0                             | 0 (제외) |

→ 양떼목장, 안목해변, 주문진, 망원시장 순으로 나온다.

### 규칙을 고칠 때

점수 숫자는 코드가 아니라 **설정 파일 한 곳**에 둔다. 데이터를 보고 숫자만 바꿔서 실험한다.

## 6. 데이터 구조

Supabase에 표 4개. 경험 표는 배포할 때 한 번 가져와서 굳히고, 나머지 3개는 실시간으로 쌓는다.

### 표 1. `experiences` (경험)

| 칸 이름                 | 종류      | 설명                                 | 예시                                                    |
| ----------------------- | --------- | ------------------------------------ | ------------------------------------------------------- |
| id                      | 번호      | 자동                                 | 12                                                      |
| slug                    | 글자      | 주소에 쓰는 이름, 영어 소문자·하이픈 | `daegwallyeong-sheep-farm`                              |
| name_en                 | 글자      | 영어 이름                            | Daegwallyeong Sheep Farm Walk                           |
| tagline_en              | 글자      | 한 줄 설명                           | A quiet hillside walk above the clouds                  |
| why_not_seoul_en        | 글자      | 왜 여기인가 한 줄                    | Korea's highlands — nothing like this exists near Seoul |
| description_en          | 긴 글자   | 소개 글 150~300단어                  | …                                                       |
| how_to_get_there_en     | 글자      | 가는 법                              | KTX to Gangneung, then bus 20 min                       |
| region                  | 글자      | 지역 코드                            | `gangneung` / `seoul`                                   |
| interest_tags           | 목록      | 관심 태그                            | `["nature","slow"]`                                     |
| style_tags              | 목록      | 스타일 태그                          | `["slow","active"]`                                     |
| duration                | 글자      | 걸리는 시간                          | `1-2h` / `half-day` / `full-day`                        |
| price_level             | 글자      | 가격대                               | `free` / `low` / `mid` / `high`                         |
| best_time               | 글자      | 좋은 때                              | Spring–Autumn, morning                                  |
| english_ease            | 숫자 1~5  | 영어 편한 정도                       | 3                                                       |
| localness               | 숫자 1~5  | 현지감                               | 5                                                       |
| booking_required        | 예/아니오 | 예약 필요                            | false                                                   |
| map_url                 | 글자      | 구글 지도 링크                       | https://maps.google.com/...                             |
| image_urls              | 목록      | 사진 주소                            | `["..."]`                                               |
| shorts_url              | 글자      | 관련 쇼츠 링크 (없으면 비움)         | https://...                                             |
| related_slugs           | 목록      | 관련 경험                            | `["anmok-beach-dawn-coffee"]`                           |
| is_published            | 예/아니오 | 사이트에 보일지                      | true                                                    |
| created_at / updated_at | 날짜      | 자동                                 |                                                         |

다국어 준비: `_en`이 붙은 칸은 나중에 `_es`, `_fr` 칸을 옆에 추가한다. 태그·지역·점수는 언어와 상관없으니 그대로.

### 표 2. `sessions` (한 사람의 한 번 방문)

| 칸 이름    | 설명                                                                           |
| ---------- | ------------------------------------------------------------------------------ |
| id         | 자동 번호                                                                      |
| started_at | 첫 화면에서 시작 누른 시각                                                     |
| source     | 어디서 왔는지 (`tiktok`, `instagram`, `google`, `direct`) — 주소 뒤 `?src=` 값 |
| language   | `en`                                                                           |
| device     | `mobile` / `desktop`                                                           |
| completed  | 질문 3개 다 답했는지                                                           |
| last_step  | 마지막으로 본 질문 번호 (이탈 지점)                                            |

### 표 3. `answers` (질문 답)

| 칸 이름        | 설명             |
| -------------- | ---------------- |
| id             | 자동             |
| session_id     | 표 2 연결        |
| interests      | 질문 1 답 목록   |
| visited_before | 질문 2 답        |
| style          | 질문 3 답        |
| result_slugs   | 보여 준 카드 8개 |
| answered_at    | 시각             |

### 표 4. `events` (행동 기록)

| 칸 이름         | 설명                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------- |
| id              | 자동                                                                                        |
| session_id      | 표 2 연결                                                                                   |
| event_type      | `card_click` / `detail_view` / `map_click` / `shorts_click` / `email_submit` / `start_over` |
| experience_slug | 관련 경험 (있을 때)                                                                         |
| created_at      | 시각                                                                                        |

### 표 5. `emails` (이메일 명단)

| 칸 이름                            | 설명                              |
| ---------------------------------- | --------------------------------- |
| id                                 | 자동                              |
| email                              | 이메일 (중복 불가)                |
| session_id                         | 어느 방문에서 남겼는지            |
| interests / visited_before / style | 그때 고른 답 (나중에 맞춤 메일용) |
| result_slugs                       | 받은 카드 목록                    |
| subscribed                         | 구독 중인지 (해지 시 false)       |
| created_at                         | 시각                              |

### 접근 권한 (꼭 지킬 것)

- `experiences`: 누구나 읽기만, 쓰기는 나만
- `sessions`, `answers`, `events`, `emails`: 사이트에서 **추가만** 가능, 읽기·수정·삭제는 나만
- 이걸 안 하면 이메일 명단이 외부에 노출될 수 있다

## 7. 측정할 지표와 어디서 볼 것인지

| 지표          | 계산                                | 어디서 보나                      |
| ------------- | ----------------------------------- | -------------------------------- |
| 방문자 수     | 첫 화면 열린 수                     | Vercel Analytics (무료)          |
| 시작률        | `Find my Korea` 누른 수 ÷ 방문자    | sessions 표 개수 ÷ Vercel 방문자 |
| 질문 완료율   | completed=true ÷ sessions 전체      | Supabase에서 세기                |
| 이탈 지점     | last_step 별 개수                   | Supabase                         |
| 취향 분포     | interests 별 개수                   | Supabase                         |
| 재방문객 비율 | visited_before 별 개수              | Supabase                         |
| 카드 클릭률   | card_click 있는 session ÷ completed | Supabase                         |
| 인기 경험     | card_click 많은 slug 순             | Supabase                         |
| 이메일 등록률 | emails 수 ÷ completed               | Supabase                         |
| 유입 경로     | source 별 개수                      | Supabase                         |

**보는 방법**: 처음엔 Supabase 화면에서 직접 센다. 매주 일요일 10분. 위 표를 구글 스프레드시트에 주 단위로 옮겨 적는다. 지표 화면을 따로 만들지 않는다.

**함께 기록할 것 (BM 문서 4번)**: 쇼츠 댓글·이메일 답장에서 나온 질문을 `질문 / 날짜 / 반복 횟수 / 연결 BM` 표로 적는다.

## 8. 다국어 확장 준비

지금 하는 것 (영어만 있지만 구조는 다국어):

1. **주소에 언어 넣기**: 모든 페이지가 `/en/...`으로 시작. 나중에 `/es/...` 추가.
2. **화면 문장을 파일로 분리**: 버튼·안내 문구를 코드에 직접 쓰지 않고 `en.json` 파일 한 곳에 모은다. 스페인어는 `es.json` 하나 더 만들면 끝.
3. **경험 데이터의 글자 칸에 `_en` 붙이기**: 위 표 1 참고.
4. **첫 화면에 언어 표시 자리 두기**: 지금은 `EN`만 보이고 눌리지 않음.
5. **날짜·가격 표기는 코드에서 한 번에 바꿀 수 있게** 한 곳에서 처리.

나중에 언어를 추가할 때 순서:

```text
es.json 만들기 (AI 초벌 번역 → 원어민 팔로워 검수)
  ↓
experiences 표에 name_es, tagline_es, why_not_seoul_es, description_es, how_to_get_there_es 칸 추가
  ↓
/es/ 주소 열기
  ↓
첫 화면 언어 버튼 활성화
```

언어 순서 제안: 영어 → 스페인어 → 프랑스어·독일어 → 포르투갈어. 실제 순서는 쇼츠 댓글의 나라 분포를 보고 정한다.

## 9. 개발 순서 (총 4주)

### 1주차 — 뼈대와 데이터

- Next.js 프로젝트 만들기, `/en/` 주소 구조, `en.json` 문장 파일
- Supabase 프로젝트 만들기, 표 5개 만들기, 접근 권한 설정
- 경험 데이터 **10개만** 먼저 넣기 (강릉 6 + 서울 4) — 나머지는 개발과 동시에 작성
- 결과: 빈 화면이지만 주소·데이터가 연결된 상태

### 2주차 — 화면 4장

- 첫 화면, 질문 화면, 결과 화면, 상세 페이지 만들기
- 추천 규칙 코드 + 설정 파일
- 폰 화면 기준으로 먼저 만들고, PC는 나중에 맞춤
- 결과: 혼자 처음부터 끝까지 눌러볼 수 있는 상태

### 3주차 — 저장과 이메일

- sessions / answers / events 저장 붙이기
- 이메일 저장 + 결과 메일 발송 (Resend 같은 무료 발송 서비스)
- 경험 데이터 40개 채우기, 사진 준비
- 상세 페이지 검색 최적화 (제목, 설명, 사이트맵)
- 결과: 실제 사용자가 써도 되는 상태

### 4주차 — 확인하고 내보내기

- 지인 5명에게 폰으로 써 보게 하고 막히는 곳 고치기
- 속도 확인 (폰에서 3초 안에 열리는지)
- Vercel에 배포, 도메인 연결
- 쇼츠 프로필 링크 교체 (`?src=tiktok` 등 붙여서)
- 결과: 출시

### 매주 지킬 것

- 금요일마다 "이번 주 만든 것"을 쇼츠 하나로 만든다 (제작 과정도 콘텐츠)
- 기능을 더 넣고 싶어지면 10번 목록에 적고 참는다
